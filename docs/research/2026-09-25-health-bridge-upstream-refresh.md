# Health Bridge upstream refresh for full-history design

Research date: 2026-09-25. This is a source inspection, not a test of the installed Home Assistant integration. The baseline in [`docs/health-bridge-protocol.md`](../health-bridge-protocol.md) is upstream `3d227252e80cdd42827f026082230215197bd583` / v1.2.1.

## What did **not** change for historical durability

- **Backfill protocol remains v1**, separate from the live protocol, which also remains v1. The explicit webhook request still requires the v1 number and resolves existing sensor entities. It now accepts a mixed numeric/text batch but does not accept original HealthKit sample UUIDs, source identity, or a durable original-sample schema. [protocol versions and text metric declaration](https://github.com/gregt1993/Health_Bridge/blob/399c6aa3c7af32d0d2faa49ae71286695532c0cb/custom_components/health_bridge/__init__.py#L23-L88), [request parser](https://github.com/gregt1993/Health_Bridge/blob/399c6aa3c7af32d0d2faa49ae71286695532c0cb/custom_components/health_bridge/__init__.py#L361-L426), [text conversion](https://github.com/gregt1993/Health_Bridge/blob/399c6aa3c7af32d0d2faa49ae71286695532c0cb/custom_components/health_bridge/__init__.py#L437-L491).
- The same **14-day** age/span limit (+15-minute grace), **2,500** points/request, **721** points/entity, SQLite-only and recorder schema **53** guards remain. Text rows may contain one or more historical points (unlike numeric series, which require a historical plus a live point); text state is capped at 255 characters and serialized row attributes at 16,384 characters. Both types deduplicate by entity and rounded second, which can collapse distinct same-second HealthKit samples and is not stable sample-ID idempotency. [limits and models](https://github.com/gregt1993/Health_Bridge/blob/399c6aa3c7af32d0d2faa49ae71286695532c0cb/custom_components/health_bridge/history_backfill.py#L23-L124), [validation](https://github.com/gregt1993/Health_Bridge/blob/399c6aa3c7af32d0d2faa49ae71286695532c0cb/custom_components/health_bridge/history_backfill.py#L138-L294), [recorder dedup/inserts](https://github.com/gregt1993/Health_Bridge/blob/399c6aa3c7af32d0d2faa49ae71286695532c0cb/custom_components/health_bridge/history_backfill.py#L420-L565).
- The acknowledgement still says `statistics_policy: "history_only"`, and the code commits backdated rows to recorder `States`/`StateAttributes`, not a sample archive or Home Assistant long-term statistics. This means v2.1.0 does **not** meet the requested multi-year raw-sample retention or long-term-statistics requirement. [acknowledgement](https://github.com/gregt1993/Health_Bridge/blob/399c6aa3c7af32d0d2faa49ae71286695532c0cb/custom_components/health_bridge/history_backfill.py#L101-L125), [recorder transaction](https://github.com/gregt1993/Health_Bridge/blob/399c6aa3c7af32d0d2faa49ae71286695532c0cb/custom_components/health_bridge/history_backfill.py#L415-L579).

## Fork implications

1. Base the installable fork on **v2.1.0 / `399c6aa…`**, not the earlier v1.2.1 snapshot. Preserve both companion app paths, all 111 registered metric keys, existing live v1 acknowledgements, v1 backfill for older clients, and v2.1.0 workout/sleep text-history behavior. Do not let a new archive route treat Phone Assistant Link payloads as HealthKit data. [v2.1.0 code](https://github.com/gregt1993/Health_Bridge/tree/399c6aa3c7af32d0d2faa49ae71286695532c0cb/custom_components/health_bridge).
2. Add a **separately capability-negotiated v2 original-sample import** (or a distinct request type) with HealthKit sample identity/provenance, bounded resumable batches, corrections/deletions, and durable server-side acknowledgement. It must coexist with v1, not reinterpret v1 `timestamp`/`value` points as originals. This is a design recommendation inferred from the v1 parser and recorder-only storage above.
3. Derive hourly Home Assistant long-term statistics and recent recorder states from the archived originals, with metric-specific aggregation rules; keep old raw originals queryable/exportable through a controlled archive API/UI. Text workout/sleep rows cannot be represented as numeric statistics without an explicit derived metric. This is a proposed design, not functionality of the current upstream release.

Unverified: the user's installed Home Assistant/Health Bridge version, the third-party iOS app's exact mapping for all 19 keys, and behavior on recorder schemas other than 53. No live Home Assistant changes were made in this research.
